# Space Inspector

Windows 10/11용 로컬 파일 검색·인덱싱·중복 분석 도구입니다. 한국어 WPF UI와 C# / .NET 10, SQLite를 사용합니다.

현재 버전은 **v2.9 미리보기 — 통합 검색·미디어 정리**입니다. 드라이브/폴더 모드, 하위 폴더 포함 여부, 파일 종류를 선택해 바로 탐색과 중복 비교를 실행합니다. 권한 대기 항목만 보류하며 나머지 작업을 계속하고, 중단해도 이미 검증한 결과를 보존합니다.

[새 버전 사용법·저장 위치·검증 범위](docs/V2_RELEASE.md)와 [재개발 계획](docs/REDEVELOPMENT_PLAN.md)을 참고하세요. 이전 전체 인덱스는 자동으로 분석하지 않으며 기존 데이터는 그대로 보존합니다. 새 작업은 독립된 인덱스와 결과 스냅샷을 저장합니다.

v2.9는 통합 필터와 저장 조건, 목록/썸네일 보기, 이미지 비교, 동영상 대표 장면과 오디오 5초 재생을 제공합니다. 단일/일괄 이동·이름 변경, 다른 볼륨으로 검증된 복사 후 원본 제거, 선택 파일들의 변경 되돌리기를 지원합니다. 실행 전 경로를 확인하고 충돌 시 덮어쓰지 않으며 중단 시 완료 내역을 보존합니다.

GitHub에서 실행본을 받으려면 성공한 [Windows build](https://github.com/ktarot/space-inspector/actions/workflows/build.yml)의 **SpaceInspector-win-x64** 아티팩트를 내려받아 전체를 풀고 `SpaceInspector.exe`를 실행하세요. 별도 .NET 런타임 설치는 필요 없습니다. 소스에서 미리보기 도우미용 실행본을 만들려면 .NET 10 SDK로 다음을 실행합니다.

```powershell
dotnet publish src/SpaceInspector.App -c Release -r win-x64 --self-contained true -o artifacts/SpaceInspector-v2.9
```

이후 저장소의 `Space Inspector 미리보기.cmd`를 열면 됩니다. 실행본·개인 DB·검사 결과는 Git에 포함하지 않습니다. 로컬 검증은 110개 통과, 환경상 링크 테스트 2개 건너뜀이며 교차 볼륨 테스트는 개발용 두 번째 볼륨 설정이 필요합니다. 세부 제약과 검증 방법은 배포 안내를 참고하세요.

아래 Phase 1~4 안내는 **이전 배포본의 구현 이력**입니다. 현재 실행 흐름은 위 v2 사용법을 따릅니다.
## Phase 4 실행

1. 기존 앱을 종료하고 새 ZIP을 별도 폴더에 풀어 실행합니다. 기존 DB는 스키마 v3로 갱신되며, 변경 전에 같은 데이터 폴더에 `index.db.schema2-backup-*.db` 백업을 만듭니다. 업그레이드 후 예전 실행 파일은 새 DB를 지원하지 않습니다.
2. 기존 인덱스에는 장치 식별 정보가 없으므로 **중복 분석 대상 범위를 한 번 재검사**하세요. 파일 목록의 볼륨 식별 열에서 연결 여부를 확인할 수 있습니다. 검색은 기존 인덱스 그대로 가능합니다. 식별 미확인 파일의 탐색기 연결은 잘못된 장치를 열지 않도록 재검사를 안내합니다.
3. **중복 분석** 탭에서 크기 후보/부분 해시/전체 SHA-256 중 수준을 선택하고 시작합니다. 현재 대상은 **저장 인덱스 전체**이며 검색 필터와는 별개입니다. 새 분석은 이전 중복 판정을 초기화합니다.
4. 그룹을 선택하고 **선택 그룹 파일 보기**를 누르면 경로를 비교할 수 있습니다. 그룹과 파일을 각각 100개씩 조회합니다. 미검증 행에서는 검사 실패/제외 사유를 확인할 수 있습니다.
5. **취소**로 분석을 중단할 수 있으며, 중단된 분석을 확정 중복으로 게시하지 않습니다. 파일 삭제·이동은 아직 구현하지 않았습니다.

파일 크기와 전체 SHA-256이 일치하고 검사 중 변경이 감지되지 않은 파일만 확정합니다. 0바이트 파일도 처리합니다. 시스템·프로그램·AppData 및 시스템 속성 파일은 기본 제외이며 옵션으로 포함할 수 있습니다. 링크/Junction 경로, 파일 reparse point, 온라인 전용/회수 속성, 다른 장치, 접근 불가·잠김·변경 파일은 콘텐츠를 검증하지 않습니다. OneDrive 실환경 무다운로드 검증은 후속 확인이 필요합니다.

하드링크는 볼륨과 128비트 파일 ID로 구분해 같은 데이터로 집계합니다. 표시하는 중복량은 `(서로 다른 데이터 수 - 1) × 논리적 파일 크기` 추정치이며, 압축·희소 파일·범위 밖 하드링크 등을 반영한 실제 확보 가능 바이트는 아직 계산하지 않습니다. 결과는 검사 시점의 스냅샷입니다.

볼륨 GUID/일련번호와 상대 경로를 저장하므로, 같은 외장 볼륨이 다른 드라이브 문자로 재검사되면 기존 인덱스를 연결합니다. 다른 장치가 같은 문자를 사용하면 기존 항목을 덮어쓰지 않습니다. 식별 실패나 연결 해제 시 행을 삭제하지 않습니다. 실시간 장치 감지/자동 경로 갱신은 후속 기능입니다.

## Phase 3 검색

검색 취소 보완판(Phase 3.1): 검색·정렬·페이지 조회 중에도 상단 **취소** 버튼을 사용할 수 있습니다. 실행 중인 SQLite 조회를 중단하고 이전 결과를 유지합니다. 검색 중 창을 닫아도 취소 후 종료합니다. 초기화 조회를 취소한 경우 **저장 인덱스 새로고침**으로 다시 시작하세요.

- **검색 조건** 탭에서 파일명 포함, 여러 확장자, 최소/최대 크기(MiB), 생성일/수정일을 입력한 뒤 **검색 적용**을 누릅니다. 모든 조건은 AND로 적용하며 확장자끼리는 OR입니다. 파일명은 부분 문자열 그대로 비교하며 와일드카드를 사용하지 않습니다.
- 날짜 끝값은 해당 날짜 하루를 포함합니다. 날짜 입력은 PC 현지 시각 기준이며 결과의 수정 시각 열은 UTC입니다. 1 MiB = 1,048,576바이트입니다.
- 기본 검색 범위는 저장 인덱스 전체입니다. **위에서 선택한 드라이브·폴더로 검색 범위 제한**을 체크하면 해당 범위만 검색합니다. 선택 범위가 없으면 안내합니다.
- 정렬 기준과 내림차순을 선택한 뒤 검색을 적용하면 전체 결과를 정렬한 후 200개씩 표시합니다. **조건 초기화**로 전체 인덱스를 다시 봅니다.
- **기준 파일 선택**은 선택 파일의 이름·확장자를 검색 조건으로 가져옵니다. 파일 내용은 비교하지 않습니다.
- 결과에서 파일을 선택한 뒤 **경로 복사**, **탐색기에서 위치 열기**를 사용할 수 있습니다. 없는 파일이나 접근할 수 없는 파일은 안내합니다. 온라인 전용 파일의 탐색기 동작은 사용자 요청으로 실행됩니다.
- 재실행/새로고침 시 마지막 검사 요약과 오류/건너뜀 기록을 복원합니다. 오류 탭은 최대 100개를 표시합니다.

Phase 2와 같은 `%LOCALAPPDATA%/SpaceInspector/index.db`를 사용하므로 기존 인덱스를 재검사 없이 검색할 수 있습니다. 기존 앱을 종료하고 새 폴더에 압축을 풀어 실행하세요. 사용자 경로 및 DB는 GitHub에 포함하지 않습니다.

## 사용 순서

1. 드라이브를 선택하거나 **폴더 추가**로 검사 범위를 지정합니다. 전체 로컬 드라이브는 **전체 선택**을 누릅니다.
2. **검사 시작 / 재검사**를 누르면 파일명, 경로, 크기, 생성·수정 시각, 파일 속성을 수집합니다. 겹치는 상위·하위 폴더는 한 번만 검사합니다.
3. **취소**하면 현재 저장 작업을 마치고 중단합니다. 이미 저장된 결과는 남습니다. 중단된 검사에서 미검사 파일을 삭제·없음으로 처리하지 않습니다.
4. **저장된 파일**에서 200개씩 조회하고, **마지막 검사 오류 / 건너뜀**에서 최대 100개 기록을 확인합니다. 전체 오류·범위·검사 결과는 DB에 남습니다.
5. 같은 범위로 다시 검사하면 기존 항목을 갱신합니다. 다른 범위의 인덱스는 유지합니다. 접근하지 못한 영역은 별도 상태를 표시하며 기존 행을 삭제하지 않습니다.

다시 실행하면 저장된 파일 목록과 마지막 검사 기록을 불러옵니다. 새로고침은 저장 인덱스를 읽으며 자동으로 파일 검사를 시작하지 않습니다.

## 실행

개발 환경: Windows 10/11 x64, .NET 10 SDK.

```powershell
dotnet restore SpaceInspector.slnx
dotnet build SpaceInspector.slnx -c Release --no-restore
dotnet test SpaceInspector.slnx -c Release --no-build
dotnet run --project src/SpaceInspector.App
```

자체 포함형 실행 파일 생성:

```powershell
dotnet publish src/SpaceInspector.App -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

`artifacts/win-x64/SpaceInspector.exe`를 실행합니다. 배포 시 해당 폴더 전체가 필요합니다. GitHub Actions의 성공한 `Windows build` 실행에서 `SpaceInspector-win-x64` 아티팩트를 내려받아 압축을 풀고 실행할 수도 있습니다. .NET 런타임을 별도 설치할 필요는 없습니다. 자동 Release 생성은 하지 않습니다.

## 데이터와 안전성

- 앱 데이터베이스: `%LOCALAPPDATA%/SpaceInspector/index.db`
- 원본 파일의 내용, 권한, 이름 또는 저장 위치를 변경하지 않습니다.
- 현재 드라이브 조회는 로컬 고정·이동식 드라이브만 대상으로 합니다. 매핑된 네트워크 드라이브는 제외합니다.
- 검사 엔진은 파일 콘텐츠를 열지 않습니다. 디렉터리 링크/Junction 및 오프라인·회수 속성이 있는 폴더는 건너뛰며, 명시적으로 선택한 경로의 상위 폴더도 확인합니다.
- 앱의 네트워크 통신, 해시 및 클라우드 다운로드 기능은 없습니다. OneDrive 실환경 무다운로드 검증 및 상세 상태 분석은 Phase 6에서 수행합니다. 속성만으로 클라우드 여부를 판단할 수 없는 파일은 미검증으로 표시합니다.
- 앱 데이터 폴더와 실행 폴더는 검사에서 제외합니다. 인덱스를 사용하는 앱은 파일 잠금으로 중복 실행을 방지합니다.
- SQLite, 검사 로그, 개인 설정 및 빌드 산출물은 Git에서 제외합니다.
- 테스트는 임시 폴더의 합성 데이터만 사용합니다.

## 구조

- `src/SpaceInspector.App`: WPF 화면, MVVM, 앱 구성
- `src/SpaceInspector.Core`: 모델과 서비스 계약
- `src/SpaceInspector.Infrastructure`: 로컬 드라이브 조회, SQLite 스키마
- `tests/SpaceInspector.UnitTests`: 대시보드/검사 명령 상태 및 WPF 창에서 검사 후 결과 표시
- `tests/SpaceInspector.IntegrationTests`: SQLite 마이그레이션, 실제 임시 파일 검사, 재검사·취소·페이지 조회·Junction 등

Junction 생성 테스트는 기본 로컬 환경에서 건너뛰며, 이를 허용하는 Windows 환경에서 `$env:SPACE_INSPECTOR_JUNCTION_TEST='1'`로 실행합니다. GitHub Actions에서는 항상 활성화합니다. 일반 테스트는 사용자 파일이 아닌 임시 합성 데이터만 사용합니다.
