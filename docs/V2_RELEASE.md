# v2 — 선택 범위 탐색·비교

2026-11-18. [재개발 계획](REDEVELOPMENT_PLAN.md)의 축소된 기능 범위를 구현한다. 기존 Phase 4 화면 대신 새 작업 화면을 사용한다.

## 실행

1. 이전 Space Inspector를 종료한다. 새 ZIP 전체를 별도 폴더에 풀고 `SpaceInspector.exe`를 실행한다. .NET 별도 설치는 필요하지 않다.
2. 드라이브 또는 폴더 모드를 선택하고 대상을 추가한다. 하위 폴더 포함 여부를 정한다.
3. 이미지/동영상/오디오/임시 파일 후보 및 추가 확장자를 정한다. 추가 확장자는 쉼표 또는 공백으로 구분한다. FLA는 확장자 선택만 지원하며 재생/미디어 해석 기능은 아니다.
4. **탐색·비교 시작**을 누른다. 선택 조건에 해당하는 파일만 수집하고 크기 → 부분 SHA-256 → 전체 SHA-256 → 변경 확인 순서로 비교한다.
5. **중단 · 결과 보존**을 누르면 이미 검증한 결과와 후보를 보존한다. 미처리 후보와 미검증 사유도 결과 탭에 표시한다. 아직 탐색하지 않은 영역의 파일 개수는 알 수 없다. 중복 그룹을 선택하면 그룹 파일이 자동 표시되며 100개 초과일 때만 페이지 이동 버튼이 나타난다.
6. **응답 대기 · 제외** 탭에서 항목을 재시도하거나 건너뛴다. **권한 요청**은 Windows UAC 승인이 필요한 별도 보조 프로세스를 시작한다. 승인 대기 중에도 주 작업은 다른 경로를 처리한다. 권한 상승 후에도 링크/온라인 전용 파일 보호 규칙을 유지한다. 권한을 자동 변경하지 않는다.
7. **저장된 작업**에서 최근 100개 작업을 다시 연다. 새 작업은 과거 결과를 지우지 않는다. 파일명 검색은 열린 작업 안에서만 수행한다.
8. 확인된 중복 그룹의 추가 복사본은 선택 후 **선택 중복 파일 휴지통 이동**을 사용할 수 있다. 그룹의 다른 확인된 데이터 복사본이 남는지 확인하며 실행 직전에 파일과 장치가 그대로인지 검사한다. 별도 확인 후 Windows 휴지통으로 이동한다. 복원은 Windows에서 직접 수행한다.

## 저장과 호환성

새 작업은 `%LOCALAPPDATA%\SpaceInspector\jobs\<작업 ID>`에 설정(`job.json`), 작업 인덱스(`index.db`), 분석 결과 스냅샷(`result-*.db`)을 저장한다. 선택 범위를 분리하기 위해 기존 전체 인덱스를 자동으로 가져오지 않는다. 기존 `%LOCALAPPDATA%\SpaceInspector\index.db`는 수정하지 않는다. 재시도 분석도 이전 결과 DB 파일을 보존하며 화면은 해당 작업의 최신 결과를 표시한다.

탐색과 비교 단계에서는 원본 파일을 수정·이동·삭제하지 않는다. 명시적으로 선택한 확인 중복 파일을 휴지통으로 보내는 관리 동작은 제공한다. 페이징/스왑/최대절전 파일은 대상 확장자로 추가해도 비교에서 제외한다. 임시/캐시 확장자 프리셋은 후보 선택 기능이며 삭제 가능 판정이 아니다. 선택 범위의 로컬 앱 데이터 파일도 읽을 수 있으므로 사용자가 지정한 범위와 확장자가 중요하다.

볼륨 식별 정보는 작업 시작 시 고정한다. 다른 장치가 같은 드라이브 문자를 차지하면 대기로 남긴다. 실행 중 드라이브 문자가 바뀐 작업을 자동 재연결하지 않는다. 새 위치를 선택해 새 작업을 시작할 수 있다.

## 상태와 제약

- 초기화/탐색/부분 해시/전체 해시/결과 조회 단계, 경과 시간, 발견 및 처리 수, 읽은 바이트, 응답 대기 수를 표시한다. 총량이 불명확한 작업에 임의의 완료 퍼센트를 표시하지 않는다. 권한 보조 작업의 읽기량은 파일 처리가 끝난 뒤 합산한다.
- 재시도는 진행 중이면 큐에 넣고 현재 탐색/분석 단계가 끝난 뒤 처리한다. 파일 한 개의 메타데이터 재시도는 같은 선택 범위 안의 부모 폴더를 다시 확인할 수 있다. 비교 결과의 일관성을 위해 알려진 작업 파일 전체를 다시 분석하며, 이전 결과 스냅샷은 남긴다.
- 취소 이후 권한 승인만 도착해도 자동 재개하지 않는다. 사용자 재시도 동작으로 다시 처리한다. 강제 종료된 분석은 다음 결과 조회 때 저장된 해시를 부분 결과로 복구한다. 결과는 검사 시점 기준이며 현재 파일 상태를 영구 보증하지 않는다.
- 응답 대기 목록은 오류 원인과 폴더별로 묶어 표시하고, 묶음을 선택하면 전체 경로 및 이유를 가로 스크롤로 확인한다.
- 드라이브 루트의 `$RECYCLE.BIN` 및 `System Volume Information`은 보호 폴더로 건너뛰며 권한 응답 대기 목록에 넣지 않는다.
- 휴지통 이동은 확인된 추가 복사본에만 제공한다. 파일 존재/장치/변경 상태와 남길 데이터 복사본을 재확인한다. 사용자가 확인하면 Windows 휴지통에 넣고 현재 작업 인덱스와 결과에서 해당 파일을 갱신한다.
- 중복량은 하드링크를 구분한 논리적 추정치다. 실제 할당 공간이나 실제 삭제 시 확보량이 아니다.
- 일반 파일 읽기는 순차 처리하고 목록은 페이지로 조회한다. OS/장치가 블로킹한 I/O는 즉시 취소를 보장할 수 없다. 상시 백그라운드 서비스, 부하 상한, 일시 정지/자동 이어 하기, 자동 변경 감시, 파일 이동/삭제는 이번 버전에 포함하지 않는다.
- 작업 및 분석 스냅샷이 누적되면 앱 데이터 공간이 증가한다. 이번 버전은 자동 이력 삭제를 하지 않는다.

## v2.4 미리보기 — 통합 결과 화면 (로컬 개발본)

탭을 제거하고 현재 작업의 전체 결과를 한 목록에서 조회한다. 파일명, 미디어 종류, 최소·최대 MiB, 비교 상태, 보관 여부를 조합하고 **필터 적용**을 누른다. 검색은 현재 페이지가 아닌 작업 전체에 적용된다. **초기화**는 조건과 같은 중복 그룹 제한을 해제한다. 보관 필터는 현재 작업에 저장된 보관 지정만 사용한다.

**조건 저장 · 불러오기**에서 이름을 입력해 조건을 저장한다. 같은 이름은 갱신한다. 저장 조건은 jobs/saved-views.json에 기록되며 다른 작업에도 적용할 수 있다. 특정 중복 그룹 제한은 저장하지 않는다. 파일을 선택하고 **같은 중복 그룹**을 누르면 그 그룹의 파일만 조회한다. 필터를 바꿀 때 다시 탐색하지 않는다.

보기는 목록, 목록+썸네일, 크기 조절 썸네일 격자로 전환한다. **미리보기** 체크로 오른쪽 패널을 표시하고 경계선을 끌어 크기를 바꾼다. **선택 파일을 비교 기준으로**를 누른 다음 다른 파일을 선택하면 두 파일을 나란히 보여준다. 작업·검색·페이지를 바꿔 목록이 새로 로드되면 비교 기준을 해제한다. 보관 지정/해제와 확인된 추가 중복본의 휴지통 이동은 목록 및 썸네일 선택에서 사용할 수 있다.

이미지 미리보기는 JPG/PNG/BMP/GIF/TIFF의 첫 프레임을 대상으로 한다. 링크·온라인 전용 경로·장치 불일치를 거부하며 32MB 또는 4천만 화소 초과 이미지는 생략한다. 이 제한은 중복 분석 조건과 별개다. 이미지의 긴 변을 최대 640픽셀로 디코딩하고 동시 처리는 2개로 제한한다. 지원하지 않는 형식과 읽기 실패는 사유를 표시한다.

로컬 실행: 저장소의 `Space Inspector 미리보기.cmd`를 더블클릭하거나 `artifacts/SpaceInspector-preview/SpaceInspector.exe`를 실행한다. 자체 포함 Windows x64 폴더 전체가 필요하며 별도 .NET 설치는 필요하지 않다. 원격 main과 기존 배포본에는 아직 반영하지 않았다.

검증: Release 빌드 경고/오류 0. 단위/UI 11개와 통합 58개 통과, 실패 0. 하드링크/Junction 2개는 로컬 환경 설정상 건너뜀. 검색 조건의 페이지 이전 적용, 빈 보관 목록, 대소문자 경로 비교, 저장 조건 재열기, 통합 결과에서 보관 보호, 실제 합성 이미지 디코딩과 비교 기준 전환을 검사했다. 마지막 화면 정리 뒤 UI 시나리오를 다시 실행해 통과했고 합성 데이터 화면을 캡처했다. 사용자 원본 파일의 삭제나 이동은 검증에 사용하지 않았다.

후속 범위: 동영상 대표 프레임, 오디오 5초 재생, 폴더 이동·이름 변경. 폴더별 그룹핑은 이번 범위에서 제외한다. 실제 대규모 작업의 썸네일 성능 및 다양한 이미지 코덱 검증은 남아 있다.

## v2.5 미리보기 — 동영상 대표 장면·오디오 5초

파일 목록과 썸네일에서 동영상·오디오를 선택하면 오른쪽 미리보기 패널에서 확인한다. 목록 자체에서는 형식 안내를 표시하며 모든 영상/음원을 한꺼번에 열지 않는다.

- 동영상: 기본 초반(재생 시간의 10%) 화면을 무음으로 표시한다. **초반 / 중간 / 후반** 버튼은 10% / 50% / 90% 지점의 정지 화면을 표시한다. 이는 시간 위치 기준 대표 장면이며 장면 분석으로 선정한 키프레임이나 정확한 I-frame 추출 기능은 아니다. 코덱에 따라 인접 프레임을 표시할 수 있다.
- 오디오: **처음부터 5초 듣기**를 눌러야 재생한다. 약 5초 후 또는 파일 끝에 도달하면 자동 중지하며, **중지** 버튼으로 즉시 종료할 수 있다. 선택 변경·미리보기 숨기기·창 닫기는 재생 및 파일 사용을 해제한다. 비교 패널 두 곳에서 동시에 오디오를 재생하지 않는다.
- 동영상과 오디오도 이미지와 같은 로컬 장치·링크·온라인 전용 경로 검사를 통과해야 연다. 10초 동안 열지 못하거나 디코더 오류가 발생하면 사유를 표시한다. 외부 코덱/프로그램을 자동 설치하거나 파일을 변환하지 않는다.
- Windows에서 재생 가능한 형식에 한해 제공한다. 확장자 선택 가능 여부와 재생 지원은 별개다. FLA 프로젝트, 코덱이 없는 영상/음원, 손상된 파일 등은 미리보기를 제공하지 못할 수 있다.

구현은 Windows WPF MediaElement의 수동 재생과 정지 상태 탐색을 사용한다. [ScrubbingEnabled](https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.mediaelement.scrubbingenabled?view=windowsdesktop-10.0)와 [Position](https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.mediaelement.position?view=windowsdesktop-10.0)의 동작을 따른다.

검증: Release 빌드 경고/오류 0, 단위/UI 18개 통과(실패/건너뜀 0), 자체 포함 Windows x64 publish 성공. 합성 무음 WAV의 실제 Windows 디코더 재생·자동 종료와 합성 AVI의 실제 무음 열기·대표 위치 탐색을 실행했다. AVI 프레임 화면 캡처도 확인했다. 제어 테스트에서 명시적 오디오 시작, 5초 자동 종료, 동시 오디오 차단, 늦은 콜백 무시, 패널 숨김/선택 변경/오류 시 해제, 잘못된 장치·네트워크·존재하지 않는 경로 거부를 확인했다. 다양한 실환경 코덱과 장시간·대형 동영상은 별도 확인이 남는다.

실행 경로는 v2.4와 같다. 기존 앱을 종료한 뒤 저장소의 `Space Inspector 미리보기.cmd`를 다시 실행하면 **v2.5 미리보기**가 열린다. 다음 개발 단계는 폴더 이동·이름 변경과 변경 후 작업 인덱스 일관성이다.

## v2.6 미리보기 — 선택 파일 이동·이름 변경 (2026-11-21)

현재 작업의 정상 파일을 선택한 뒤 **이름 변경** 또는 **이동**을 누른다. 새 폴더/이름을 입력하면 실행 전 원래 경로와 변경 경로, 작업 범위 유지 여부를 다시 확인한다. 취소하면 파일을 변경하지 않는다. 현재 버전은 선택한 파일 한 개씩 같은 볼륨 안에서 처리한다. 다른 볼륨 이동, 일괄 변경, 대소문자만 바꾸는 이름 변경은 지원하지 않는다.

같은 이름의 파일/폴더가 이미 있으면 덮어쓰지 않는다. 이동 직전 파일 크기·수정 시각·장치·실제 파일 식별자를 재확인하고, 열린 파일 핸들로 변경한다. 링크·온라인 전용·읽기 전용·시스템 파일과 시스템/앱 보호 경로는 거부한다. 미리보기의 파일 사용을 먼저 해제하며 다른 프로그램이 잠근 파일은 변경에 실패할 수 있다.

작업 인덱스와 최신 결과 DB의 경로·파일명을 함께 갱신하며 보관 지정도 새 경로로 옮긴다. 작업 범위 안의 변경은 기존 중복 판정을 유지한다. 범위 밖 폴더로 옮기거나 대상이 아닌 확장자로 바꾸면 **작업 범위 밖으로 이동**으로 표시하고 현재 비교 대상에서 제외한다. 기존 작업 설정을 자동 확장하지 않으며 범위 밖 파일을 다시 관리하려면 해당 위치를 포함하는 새 작업을 시작한다.

작업 폴더의 file-actions에 변경 기록을 남긴다. 파일 이동 후 DB/보관 기록 갱신 전에 종료된 경우 작업을 다시 열거나 **저장된 작업 열기 → 파일 변경 기록 확인**으로 기록 갱신을 재시도한다. 복구는 확인된 파일 위치에 맞춰 기록만 정리하며 원본 파일 이동을 자동 재실행하지 않는다. 경로·장치 상태가 모호하면 자동 복구를 중지하고 사유를 표시한다. 과거 결과 스냅샷은 수정하지 않으며 다른 저장 작업에 기록된 경로는 자동으로 바꾸지 않는다.

실행: 기존 앱을 종료한 뒤 저장소의 **Space Inspector 미리보기.cmd**를 더블클릭한다. 이 실행 도우미는 이제 `artifacts/SpaceInspector-v2.6/SpaceInspector.exe`를 연다. 이전 `artifacts/SpaceInspector-preview` 폴더는 보존했다.

검증: 단위/UI 18개, 통합 70개 통과, 실패 0. 환경 설정이 필요한 하드링크/Junction 2개 건너뜀. 합성 파일로 정상 이름 변경, 보관 유지, 범위 밖 이동, 기존/경합 대상 충돌, 변경된 원본 거부, 잘못된 장치·이름·읽기 전용 거부, 부분 DB 갱신 후 복구, 시작 전 중단 기록, 범위 밖 확장자의 재탐색 상태를 검사했다. UI 명령의 취소/확인과 변경 후 화면도 검사했다. 자체 포함 Windows x64 publish 성공. 실제 사용자 파일은 테스트에 사용하지 않았다.


## v2.7 미리보기 — 일괄 변경·다른 볼륨 이동 (2026-11-21)

목록과 썸네일에서 **Ctrl/Shift로 여러 파일을 선택**한 뒤 **선택 이름 변경 / 선택 이동**을 누른다. 선택은 현재 페이지의 최대 100개 파일에 한정한다. 보기 모드 전환은 다중 선택을 유지하고, 필터/페이지/작업 재조회는 다중 선택을 해제한다(기존 미리보기 파일 한 개가 다시 선택될 수 있다). 보관 지정과 휴지통 이동은 미리보기 중인 파일 한 개에 적용한다.

- 일괄 이름 변경: 기존 이름 앞에 접두어를 붙이거나 **공통 이름 + 연속 번호**를 적용한다. 원래 확장자와 폴더를 유지하며 전체 경로 순서로 번호를 부여한다. 시작 번호를 지정할 수 있다.
- 일괄 이동: 대상 폴더를 선택하면 원래 파일 이름을 유지한다. 같은 이름이 겹치면 자동으로 이름을 바꾸거나 덮어쓰지 않는다.
- 변경 전후 경로 표 → 모든 항목 사전 검사 → 최종 확인 → 실행 순서다. 중복 대상 경로, 선택 원본 간 이름 교환, 장치 불일치, 변경된 원본 등은 실행 전에 거부한다. 실행 직전에도 다시 검사한다.
- 중단/오류가 발생하면 완료된 변경을 보존하고 나머지는 멈춘다. 결과 표에서 완료·실패·중단·미처리를 구분한다. 파일별 결과는 해당 작업의 `file-actions/reports`에 저장한다. 전체 일괄 변경의 원자적 롤백이나 자동 되돌리기는 제공하지 않는다.

**다른 볼륨 이동**은 대상 폴더의 고유 임시 파일에 복사 → 디스크 flush → 전체 SHA-256 비교 → 최종 이름으로 게시(덮어쓰기 금지) → 원본 제거 → 작업 기록 갱신 순서다. 원본과 대상 디렉터리를 핸들로 보호하고 장치·경로·파일 식별자를 재확인한다. 복사와 검증 중 **중단·결과 보존**을 누르면 원본을 유지하고 이번 실행이 연 임시 파일만 정리한다. 최종 게시가 시작된 파일은 원본 제거와 기록 갱신을 마친 뒤 다음 파일부터 중단한다. Windows 장치 I/O가 응답하지 않는 동안에는 중단이 지연될 수 있다.

파일 내용, 생성/수정 시각, 숨김·보관·내용 인덱싱 제외 기본 속성을 옮긴다. 대상 폴더의 접근 권한을 상속하며 원본 ACL·소유권·압축/희소 배치·하드링크 관계를 복제하지 않는다. EFS 암호화나 추가 데이터 스트림(예: 다운로드 보안 정보)이 있는 파일은 데이터 손실 방지를 위해 다른 볼륨 이동을 거부한다. 스트림 여부는 Windows [FindFirstStreamW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirststreamw)로 확인한다. 파일 시스템이 지원하지 않는 파일 ID/메타데이터 동작은 사유를 표시하고 중단한다. 실제 검증 대상은 NTFS 두 볼륨이다.

변경 후 인덱스와 최신 결과 DB의 볼륨·물리 파일 ID·경로·시각을 갱신하고 보관 지정을 유지한다. 대상이 기존 작업에 포함된 경로·확장자·장치일 때만 비교 범위에 남긴다. 과거 결과 스냅샷과 다른 저장 작업의 기록은 변경하지 않는다.

앱 종료로 중간 상태가 남으면 **저장된 작업 열기 → 파일 변경 기록 확인**을 사용한다. 원본이 없고 대상 파일의 식별자·전체 해시가 맞으면 DB와 보관 기록만 복구한다. 원본과 복사본이 모두 있으면 둘 다 보존하고 확인할 대상 경로를 표시한다. 중단된 임시 파일도 자동 삭제하지 않고 경로를 알린다. 장치 분리나 원본 변경으로 판단할 수 없으면 복구를 중지한다. 복구가 원본 제거 또는 이동을 자동 재실행하지 않는다.

검증: **99개 통과**(단위/UI 18, 통합 81), 실패 0. 기존 하드링크/Junction 2개는 환경 설정상 건너뜀. 임시 합성 파일로 실제 C:→E: 이동, 전체 바이트 검증, 대상 장치/파일 ID/보관 갱신, 복사·검증 중 취소, 늦은 대상 충돌, 게시 후 중단 시 양쪽 보존, 원본 제거 후 부분 DB 갱신 복구, 추가 스트림 거부, 손상된 복사본 거부를 검사했다. 일괄 사전 검사·부분 완료·취소, 목록/격자 다중 선택, 이름 규칙·최종 확인 취소/실행도 검사했다. 변경 전후 표와 결과 화면 캡처를 확인했다. 실제 사용자 파일은 테스트에 사용하지 않았다.

교차 볼륨 테스트를 재실행할 때는 `SPACE_INSPECTOR_CROSS_VOLUME_TEST_ROOT`에 TEMP와 다른 볼륨의 개발용 폴더를 지정한다. 테스트는 그 아래 자신이 만든 GUID 폴더만 사용한다. 변수가 없으면 교차 볼륨 테스트 7개는 명시적으로 건너뛴다.

실행: 기존 앱을 닫고 저장소의 **Space Inspector 미리보기.cmd**를 다시 연다. `artifacts/SpaceInspector-v2.7/SpaceInspector.exe`를 실행하며 이전 v2.6 폴더는 보존한다. 자체 포함 Windows x64 배포 폴더 전체가 필요하다. 원격 main에는 아직 반영하지 않은 로컬 개발본이다.


## v2.8 미리보기 — 선택 파일 변경 되돌리기 (2026-11-21)

파일 한 개를 선택하고 **우클릭 → 선택 파일 변경 되돌리기**를 누른다. **저장된 작업 열기** 영역에도 같은 버튼이 있다. 현재 경로와 복원할 경로를 검토하고 확인하면 현재 작업의 마지막 완료 이동·이름 변경을 되돌린다. 여러 파일을 선택하면 비활성화하며, 일괄 작업도 완료된 파일을 한 개씩 선택하여 되돌린다.

작업 범위 밖으로 옮긴 파일도 현재 결과의 기록이 남아 있으면 복원할 수 있다. 원래 폴더가 존재하고 원래 경로가 비어 있어야 하며, 장치·물리 파일 ID·크기·수정 시각·완료 기록이 맞아야 한다. 원래 경로의 다른 파일을 덮어쓰지 않는다. 다른 볼륨으로 되돌리는 경우 v2.7의 검증된 복사 절차에 더해 최초 이동 때 기록한 전체 해시와 비교한다. 크기와 수정 시각이 같아도 내용이 달라졌으면 현재 파일을 보존하고 중단한다.

되돌리기는 별도 작업 기록으로 남기며, 이미 되돌린 기록의 중복 실행을 거부한다. 파일 복원 뒤 DB 갱신 전에 종료되어도 **파일 변경 기록 확인**으로 갱신을 재시도할 수 있다. 현재 보관 지정은 복원 경로로 이어진다. 오래된 중복 판정을 복원하지 않으므로 **탐색·비교를 다시 실행**해야 중복 정리할 수 있다.

현재 작업의 최신 결과 스냅샷과 일치하는 기록만 지원한다. 다른 작업에서 바뀐 파일, 재탐색으로 결과가 교체된 이전 기록, 삭제된 원래 폴더, 변경된 파일/장치는 자동으로 복원하지 않는다. 여러 단계의 이동을 모두 되감는 기능이나 전체 일괄 작업의 원자적 롤백은 포함하지 않는다. 특히 볼륨 왕복으로 물리 파일 ID가 바뀌면 그보다 오래된 이동 기록은 거부될 수 있다. 휴지통 복원·내용 편집 취소는 이 기능의 대상이 아니다.

실행은 **Space Inspector 미리보기.cmd**로 하며 v2.8 실행 폴더를 사용한다. 이전 v2.7은 보존한다. 원격 main에 반영하기 전 로컬 개발본이다.

검증: 단위/UI 18개와 통합 86개, 합계 **104개 통과**, 실패 0, 기존 링크 환경 테스트 2개 건너뜀. 범위 밖 이동 복원과 보관 유지, 원래 경로 충돌·변경된 파일 거부, 부분 DB 갱신 뒤 복구, 실제 C:↔E: 왕복, 크기·시각을 유지한 내용 변경 거부, 확인창 취소/실행과 미검증 필터 표시를 검사했다. 사용자 파일은 테스트에 사용하지 않았다. 현재 교차 볼륨 테스트는 환경 변수를 지정하지 않으면 9개를 건너뛴다. Windows x64 자체 포함 실행본을 별도 폴더로 생성했다.


## v2.9 미리보기 — 여러 파일 변경 되돌리기 (2026-11-22)

현재 페이지에서 **Ctrl/Shift로 여러 파일을 선택 → 우클릭 → 선택 파일 변경 되돌리기**를 실행한다. 선택한 각 파일의 마지막 완료 이동·이름 변경을 찾아 현재/복원 경로 표를 보여준다. 한 번의 확인으로 최대 100개 파일을 순서대로 복원한다. v2.8의 한 파일 제한을 확장했으며 **저장된 작업 열기** 영역의 같은 버튼도 다중 선택에 적용된다.

모든 선택 파일의 완료 기록·현재 상태·대상 경로를 먼저 검사한다. 되돌릴 기록이 없는 파일이나 충돌 경로가 하나라도 있으면 문제 파일 경로를 안내하고 전체를 실행하지 않는다. 실행 직전에도 다시 검사하며, 이후 생기는 충돌이나 취소는 그 지점에서 멈추고 완료·실패·중단·미처리 결과를 표시한다. 이미 복원한 파일을 다시 옮기는 자동 롤백은 수행하지 않는다. 실패·미처리 파일을 다시 선택하면 남은 복원을 검토할 수 있다.

보관 지정과 인덱스/결과 DB를 복원 경로에 맞춰 갱신하며, 복원된 파일은 미검증으로 표시한다. **탐색·비교를 다시 실행**해야 중복 판정을 갱신할 수 있다. 다른 볼륨 복원은 전체 해시 검증 후 원래 위치로 복사하며 현재 사본을 제거한다. 기존 v2.8의 파일/장치 확인과 지원 범위 제한을 그대로 적용한다. 서로의 경로를 교환하는 복원, 이전 결과 스냅샷을 넘는 복원, 전체 작업의 원자적 롤백은 지원하지 않는다.

이미 선택된 파일을 우클릭하면 다중 선택을 유지하면서 해당 파일을 미리보기 대상으로 삼는다. 선택하지 않은 파일을 우클릭하면 그 파일 하나를 선택한다. 목록과 썸네일에 동일하게 적용하며, 단일 파일용 보관·휴지통 명령의 대상도 우클릭한 파일과 일치한다.

검증: 단위/UI 18개, 통합 92개로 **110개 통과**, 실패 0, 기존 링크 환경 테스트 2개 건너뜀. 일괄 범위 밖 복원/보관 유지, 기록 누락·경로 충돌의 사전 거부, 처리 중 취소·충돌과 남은 두 파일 재시도, 실제 C:↔E: 두 파일 왕복을 검사했다. UI에서 다중 선택 상태의 확인 취소/실행과 우클릭 선택 유지도 확인했다. 교차 볼륨 환경 변수가 없으면 관련 10개 테스트는 건너뛴다. 사용자 파일을 테스트에 사용하지 않았다.

실행: 기존 앱을 닫고 **Space Inspector 미리보기.cmd**를 연다. 별도 `artifacts/SpaceInspector-v2.9` 실행 폴더를 사용하고 v2.8은 보존한다. 원격 main에는 아직 반영하지 않은 로컬 미리보기다.


## GitHub 소스 갱신 (2026-11-22)

v2.4~v2.9에서 개발한 통합 검색·미디어 미리보기·일괄 파일 변경·되돌리기 소스와 테스트를 한 변경으로 정리했다. 위 절의 로컬 개발본/원격 미반영 표기는 각 버전 개발 당시의 이력이다. 최신 사용 및 소스 빌드 방법은 README를 따른다. Windows 실행본은 GitHub Actions의 성공한 `Windows build` 실행에서 `SpaceInspector-win-x64` 아티팩트로 제공한다. 자동 GitHub Release 생성은 수행하지 않는다.


GitHub 호스팅 Windows 러너에서는 실제 WAV 재생이 `0xC00D11BA`, 실제 AVI 열기가 제한 시간 초과로 실패했다. 해당 환경에는 `SPACE_INSPECTOR_SKIP_NATIVE_MEDIA_TESTS=1`을 지정해 실제 장치/디코더 테스트 2개만 명시적으로 건너뛴다. 가짜 세션 기반 재생·정지·오류·선택 변경 테스트와 WPF 작업 UI 검증은 계속 실행한다. 로컬에서는 이 변수를 지정하지 않아 실제 AVI/WAV 검사도 실행한다. CI의 교차 볼륨 10개와 네이티브 미디어 2개는 로컬 실환경 검증과 구분하여 보고한다.
