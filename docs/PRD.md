# 1. 프로젝트 목적

## 1.1 대전제

컴퓨터의 여러 드라이브와 폴더에 흩어져 있는 파일을 사용자가 원하는 기준으로 일목요연하게 파악하고 효율적으로 관리할 수 있는 Windows 애플리케이션을 개발한다.

## 1.2 주요 목표

1. 컴퓨터의 모든 드라이브 또는 지정된 드라이브·폴더를 검색한다.
2. 검색된 파일의 정보를 인덱스로 구축한다.
3. 파일명, 확장자, 크기, 날짜, 재생 시간 등을 기준으로 파일을 검색한다.
4. 내용이 동일한 중복 파일을 찾는다.
5. 내용이 비슷하거나 파일 정보가 유사한 중복 의심 파일을 찾는다.
6. 발견한 파일의 실제 저장 위치를 사용자에게 제공한다.
7. 시스템 파일과 프로그램 파일을 일반 사용자 파일과 구분한다.
8. OneDrive의 온라인 전용 파일과 로컬 파일을 구분한다.
9. 파일과 폴더의 접근 권한을 확인한다.
10. 디스크의 사용량과 여유 공간을 분석한다.
11. 사용자가 직접 파일을 정리할 수 있도록 지원한다.

프로그램의 핵심은 파일 자동 정리가 아니라 **파일 검색, 인덱싱, 중복 분석, 사용자 중심 파일 관리**다.

# 2. 개발 원칙

## 2.1 안전성

- 원본 파일을 변경하지 않는다.
- 파일을 자동 삭제하지 않는다.
- 파일을 자동 이동하지 않는다.
- 파일 이름을 자동 변경하지 않는다.
- 원본 파일의 권한을 변경하지 않는다.
- OneDrive 온라인 전용 파일을 자동 다운로드하지 않는다.
- 시스템 파일 및 프로그램 파일의 안전성을 우선한다.
- 접근할 수 없는 파일은 검사 실패로 기록한다.
- 사용자가 허용하지 않은 네트워크 통신을 수행하지 않는다.

## 2.2 사용자 중심 설계

- 사용자가 검색 범위를 자유롭게 지정할 수 있어야 한다.
- 사용자가 검색 조건을 조합할 수 있어야 한다.
- 검색 결과를 저장하고 다시 사용할 수 있어야 한다.
- 원본 파일의 경로를 확인할 수 있어야 한다.
- 파일을 선택하여 Windows 파일 탐색기에서 열 수 있어야 한다.
- 프로그램 내부에서 실행하는 파일 변경 작업은 후속 버전에서 사용자가 명시적으로 요청하는 수동 방식으로 구현한다.

## 2.3 데이터 정책

- 파일 인덱스는 사용자 PC에 저장한다.
- 실제 파일의 내용을 데이터베이스에 저장하지 않는다.
- 파일 정보와 검색 결과를 외부 서버에 전송하지 않는다.
- 사용자 파일 목록과 경로가 GitHub에 업로드되지 않도록 한다.
- SQLite 데이터베이스, 검사 로그, 사용자 환경 설정은 Git 관리 대상에서 제외한다.

# 3. 사용자 검색 시나리오

## SC01. 전체 드라이브 검색

사용자가 전체 드라이브 검색을 선택하면 접근 가능한 모든 로컬 드라이브를 검색한다.

작업 순서:

1. 연결된 드라이브 검색
2. 드라이브 목록 표시
3. 파일 및 폴더 정보 수집
4. 파일 인덱스 생성
5. 파일 분류
6. 중복 후보 탐색
7. 사용자가 요청한 수준까지 중복 검증
8. 검색 결과 표시

## SC02. 특정 드라이브 검색

사용자가 C:, D:, E: 등 하나 또는 여러 드라이브를 선택한다.

선택한 영역만 검색한다.

다른 드라이브에 생성된 기존 인덱스는 유지한다.

## SC03. 특정 폴더 검색

사용자가 하나 이상의 폴더를 선택한다.

선택한 폴더와 하위 폴더를 검색한다.

상위 폴더와 하위 폴더가 동시에 선택되면 동일 파일을 중복 집계하지 않는다.

## SC04. 지정 파일의 중복 검색

사용자가 특정 파일 하나를 선택한다.

해당 파일을 기준으로 전체 드라이브 또는 지정된 범위에서 동일 파일과 유사 후보를 찾는다.

검색 결과에는 파일명, 경로, 크기, 수정일, 중복 판정 결과 등을 표시한다.

## SC05. 확장자별 검색

사용자가 검색할 확장자를 선택한다.

예시:

- MP4
- MOV
- JPG
- PNG
- PDF
- DOCX
- XLSX
- ZIP
- EXE

여러 확장자를 동시에 선택할 수 있어야 한다.

사용자가 직접 확장자를 입력하는 기능도 제공한다.

## SC06. 복합 조건 검색

사용자는 다음 조건을 조합할 수 있다.

- 검색 범위
- 파일명
- 확장자
- 최소 파일 크기
- 최대 파일 크기
- 생성 날짜
- 수정 날짜
- 미디어 재생 시간
- 파일 분류
- 중복 여부
- OneDrive 상태
- 파일 접근 권한

조건 간 AND/OR 검색을 지원하도록 확장 가능한 구조로 설계한다.

초기 버전은 AND 조건을 우선 구현한다.

# 4. 파일 인덱스 시스템

## 4.1 목적

파일 검색과 중복 분석의 성능을 높이기 위해 파일 시스템 정보를 로컬 데이터베이스에 저장한다.

파일 인덱싱과 검색은 독립적인 기능으로 구현한다.

파일을 한 번 인덱싱하면 이후에는 인덱스를 이용해 빠르게 검색할 수 있어야 한다.

## 4.2 인덱스 필드

파일별로 다음 정보를 관리한다.

### 기본 정보

- FileId
- FileName
- Extension
- FullPath
- ParentDirectory
- Drive
- FileSize
- AllocatedSize
- CreationTime
- ModifiedTime
- Attributes

### 분석 정보

- FileCategory
- FileType
- PartialHash
- FullHash
- DuplicateGroupId
- DuplicateStatus
- Duration
- ScanTime

### 시스템 정보

- VolumeIdentifier
- FileSystemIdentifier
- Owner
- AccessPermission
- IsSystemProtected
- IsApplicationFile
- IsCloudPlaceholder
- OneDriveStatus
- ScanStatus
- ScanError

일부 필드는 수집할 수 없을 수 있으므로 NULL 또는 확인 불가 상태를 허용한다.

## 4.3 인덱스 상태 관리

각 인덱스 항목에는 다음 상태를 부여한다.

- 정상
- 변경 감지
- 재검사 필요
- 접근 거부
- 원본 파일 없음
- 저장 장치 연결 해제
- 확인 불가

외장 드라이브가 연결되지 않았다는 이유로 기존 인덱스 정보를 삭제하지 않는다.

## 4.4 인덱스 갱신

지원할 작업:

1. 전체 재검사
2. 선택 드라이브 재검사
3. 선택 폴더 재검사
4. 변경된 파일 정보 갱신
5. 저장된 인덱스에서 즉시 검색

초기 버전은 수동 재검사를 기본으로 한다.

파일 시스템 변경 이벤트를 이용한 실시간 인덱스 갱신은 후속 기능으로 설계한다.

# 5. 중복 파일 검사 엔진

## 5.1 중복 판정 단계

### Level 1. 파일명 일치

파일명이 동일한 파일을 찾는다.

중복 확정이 아닌 후보 검색에 사용한다.

### Level 2. 파일 크기 일치

파일의 논리적 크기가 동일한 후보를 찾는다.

### Level 3. 부분 해시 일치

파일 일부의 해시를 계산하여 후보를 축소한다.

### Level 4. 전체 해시 일치

전체 파일의 SHA-256 해시를 계산한다.

파일 크기와 전체 해시가 일치하면 확정 중복으로 분류한다.

단, 검사 중 파일이 변경되었다면 결과를 확정하지 않고 재검사 대상으로 표시한다.

## 5.2 중복 판정 상태

- ConfirmedDuplicate: 전체 해시로 검증된 중복
- StrongCandidate: 크기와 부분 해시가 일치하는 후보
- SuspectedDuplicate: 이름·크기 등 메타데이터가 유사한 후보
- NotDuplicate: 비교 결과 동일 콘텐츠가 아님
- Unverified: 검사 불가 또는 검증 미완료

## 5.3 특수 처리

다음 항목을 별도로 처리한다.

- NTFS 하드링크
- 심볼릭 링크
- Junction
- 0바이트 파일
- 읽기 권한이 없는 파일
- 다른 프로그램이 사용 중인 파일
- 검사 도중 변경된 파일
- OneDrive 온라인 전용 파일

동일한 실제 파일 데이터를 공유하는 하드링크는 추가적인 중복 저장 공간으로 계산하지 않는다.

## 5.4 미디어 중복 검색

오디오 및 비디오 파일에 대해 다음 정보를 추가로 수집한다.

- 재생 시간
- 코덱 정보
- 해상도
- 비트레이트

초기에는 재생 시간 검색부터 구현한다.

비슷한 재생 시간을 가진 파일은 중복 의심 후보로 표시할 수 있지만, 동일 콘텐츠로 확정하지 않는다.

서로 다른 인코딩 파일의 시각적·청각적 유사성 분석은 후속 버전으로 분리한다.

# 6. 파일 분류 시스템

## 6.1 기본 분류

- Windows 시스템 파일
- 프로그램 및 앱 파일
- 미디어 파일
- 문서 및 업무 파일
- 개발 프로젝트 파일
- 압축 및 설치 파일
- 임시 파일
- 백업 파일
- 기타 파일

## 6.2 시스템·프로그램 파일 사전 분류

Windows의 표준 시스템 폴더와 설치 프로그램 경로를 이용해 기본 보호 목록을 구성한다.

대표 경로:

- Windows
- Program Files
- Program Files (x86)
- ProgramData
- AppData

Windows Known Folder API 및 실제 설치 경로를 활용한다.

시스템·프로그램 관련 파일은 전체 인덱스에는 포함하지만 일반 사용자 파일 중복 검색에서는 기본적으로 제외한다.

사용자는 검색 옵션에서 포함 여부를 변경할 수 있다.

경로만으로 보호 여부를 확정할 수 없는 파일은 확인 필요로 표시한다.

## 6.3 사용자 정의 분류

사용자가 다음 조건으로 분류 규칙을 만들 수 있도록 설계한다.

- 폴더 경로
- 확장자
- 파일명 패턴
- 크기
- 날짜

사용자 정의 분류 정보는 SQLite에 저장한다.

사용자 정의 태그와 스마트 컬렉션은 기본 인덱스 구조를 변경하지 않고 추가할 수 있도록 설계한다.

# 7. OneDrive 분석

## 7.1 목적

OneDrive 파일의 논리적 크기와 실제 로컬 점유량을 구분하여 Windows 디스크 공간을 정확하게 파악한다.

## 7.2 파일 상태

- 온라인 전용
- 로컬 사용 가능
- 항상 이 장치에 유지
- 동기화 또는 상태 확인 중
- 확인 불가

## 7.3 필수 요구사항

1. OneDrive 동기화 폴더 탐지
2. 온라인 전용 파일 판별
3. 로컬 저장 파일 판별
4. 로컬 디스크 점유량 분석
5. OneDrive 내 대용량 파일 검색
6. 로컬에서 검증 가능한 중복 파일 검색
7. 자동 다운로드 방지
8. 동기화 상태 자동 변경 금지

온라인 전용 파일의 콘텐츠를 열거나 해시 계산을 시도해서 파일 다운로드가 발생하지 않도록 한다.

내용을 검사할 수 없는 파일은 미검증으로 표시한다.

# 8. 파일 접근 권한 분석

## 8.1 목적

사용자가 파일을 복사하거나 이동하기 전에 접근 권한을 확인하도록 지원한다.

## 8.2 수집 정보

- 파일 소유자
- 사용자 및 그룹별 접근 권한
- 읽기 권한
- 쓰기 권한
- 삭제 권한
- 권한 변경 가능 여부
- 권한 상속 여부
- 현재 사용자의 유효 권한

단순 ACL 정보와 실제 유효 권한은 구분한다.

## 8.3 사용자 기능

- 파일 상세 정보에서 권한 확인
- 권한 제한 파일 검색
- 접근 거부 파일 목록 확인
- 권한 확인이 필요한 파일 표시
- Windows 파일 탐색기 및 보안 속성 화면 연결

프로그램은 직접 권한을 변경하지 않는다.

# 9. 저장 공간 분석

## 9.1 드라이브 분석

드라이브별로 다음 정보를 표시한다.

- 전체 용량
- 사용 중인 용량
- 사용 가능한 공간
- 사용률
- 파일별 논리적 크기 합계
- 접근 불가 또는 집계되지 않은 영역

## 9.2 폴더 분석

- 폴더별 전체 용량
- 파일 수
- 파일 종류별 사용량
- 대용량 파일 목록
- 중복 후보 용량

## 9.3 공간 확보 가능성 분석

확정 중복 파일과 정리 후보 파일의 정보를 제공한다.

논리적 파일 크기와 실제 확보 가능한 공간을 구분한다.

확보 가능 공간은 추정치일 수 있으며 그 근거를 표시한다.

# 10. UI 설계

# 17. 최종 개발 목표

Space Inspector는 사용자에게 다음 질문에 답할 수 있어야 한다.

- 내 컴퓨터에 어떤 파일들이 저장되어 있는가?
- 파일들이 어느 드라이브와 폴더에 흩어져 있는가?
- 같은 이름의 파일은 어디에 있는가?
- 실제로 내용이 동일한 중복 파일은 무엇인가?
- 중복으로 의심되는 파일은 무엇인가?
- 특정 파일과 동일한 파일이 다른 위치에도 존재하는가?
- 특정 확장자나 크기의 파일은 어디에 있는가?
- 원하는 길이의 오디오·비디오 파일은 어디에 있는가?
- 시스템 파일과 일반 사용자 파일을 구분할 수 있는가?
- 파일의 접근 권한은 어떻게 설정되어 있는가?
- OneDrive에서 로컬 공간을 차지하는 파일은 무엇인가?
- 어떤 파일과 폴더가 저장 공간을 가장 많이 차지하는가?

이 질문에 정확하게 답할 수 있는 **사용자 중심 통합 파일 검색 및 관리 애플리케이션**을 완성한다.
